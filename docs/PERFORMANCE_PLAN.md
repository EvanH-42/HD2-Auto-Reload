# Tactical 性能优化目标与计划

更新时间：2026-10-03（Asia/Taipei）

## 1. 已确认的目标和范围

仅优化原有 tactical 输入构建的运行时成本，保留原有换弹策略和输入行为。范围止于 P3，分两步交付：第一步 P0–P2，第二步 P3。P4–P6 不在本次范围内。

- 构建目标：`python scripts/build.py --enable-tactical-reload`，不加 `--native-reload`。
- 保留各武器 `limit`、`basis`、`immediate`、`continuous` 和 attack-only 例外，不统一成 reserve=1。
- 保留最后一发/零阈值优先级、点击等待、逐发续装、发送失败重试、松键与焦点规则。
- 不加入 Fire Guard，不拦截射击，不改弹药，不新增内存写入或原生函数调用。
- 保留非战术版及原生实验版的现有入口和行为，相关已有测试仍须通过；本次实机验收目标为 tactical 输入版。
- 不实施独立的 guard 缩减、规则查找/FFI/table/logging 微优化，也不扩展武器配置、游戏布局或支持版本。
- 不擅自安装、部署、提交、推送或发布。

P0–P2 已实施并完成离线验证；保留 P1 和 P1+P2 两份独立包，均默认启用 P0 统计。P0 口径见 [PERFORMANCE_P0.md](PERFORMANCE_P0.md)，阶段对照及实机步骤见 [PERFORMANCE_P1_P2.md](PERFORMANCE_P1_P2.md)。P3 尚未实施，实机验收待完成，当前进度以 [STATUS.md](STATUS.md) 为准。

## 2. 对话提取与源码核对

来源：[分支 · 分析hd2模组接口](chatgpt-conversation://6ac0bfd4-eb64-83ee-adc0-926cb2befc36)。关键方向为：先测基线，再以完整解析建立缓存，用快速读取提供相同 row；固定采样频率后再引入自适应频率；执行换弹前继续完整复核。对话中的读次数、收益比例及 30/60/120 Hz 均是设想，不是实测结果。

## 3. 第一步：P0–P2

### P0：建立可比较的基线

先验证现有测试，再增加轻量、可关闭的统计与可重复离线测量。不开逐帧日志，不用完整 DEBUG 日志代替性能测量。

统计口径至少包含：update 次数、采样尝试/成功/失败、完整解析/快速读取次数、缓存命中/失效原因、读取尝试/成功/失败与请求字节数、guard 复读、静态 map 验证、普通及续装发送前复核次数。初始化读取、日常采样和发送复核分开记账；失败读取同样计入，避免只统计成功 row。计数器不得改变原读取预算和错误处理。

耗时测量使用可用且分辨率足够的时钟，注明是离线模拟还是游戏内数据。现有毫秒时钟不足以可靠测量单次短读取，可采用批量测量；没有可靠计时工具时先报告读取量，不声称 CPU 降幅。统计启用/关闭的额外成本也需检查。

离线场景覆盖 Magazine、Rounds、Heat，以及稳定装备、切枪、身份重建、读取失败与发送复核。比较基线/P1/P2/P3时使用相同内存夹具、轨迹、时间长度和帧率；至少覆盖 60、120、144、240、360 FPS。输出实际采样频率、每秒读取量、每次读取量、回退率和可测耗时，保留可复现命令。

完成条件：基线自动测试结果、测量口径和原始摘要可复核；无实际数据的项目明确标记待测。离线结果不能代替游戏内基线。

### P1：完整解析建立缓存，日常快速读取

完整 context_reader 保留完整 map/布局/配置/身份及一致性验证，用于首次解析、缓存重建、异常回退和所有发送前复核。只有成功且可行动的完整上下文允许建立缓存；未解析或不支持的状态不建立可用弹药缓存。

缓存元数据包含：玩家/Avatar/owner 身份、物品栏与选择槽位、武器实体和完整身份、driver/ammo manager 与组件索引、registry 与状态/runtime 基址、配置来源/override 身份及静态配置。缓存具体字段以实现审查为准，不预先虚构游戏可用的 generation 标识。

快速读取应满足：

1. 所有读内存继续走现有安全 api.read；不改成裸指针解引用。
2. 验证缓存依赖的 manager、数组/registry 基址、索引边界、实体所有权、槽位/武器和组件身份；读前/读后检查覆盖可能变化的依赖。
3. 读取 Magazine 的 count/chamber/blocked、Rounds 的 selected magazine/count/chamber/blocked、Heat 的锁定/备用数量/热值等动态字段，使用同一解析口径与合法性约束。
4. 配置 override、map 或对象可能原地变化时，必须设计可验证的失效检查。不能只靠相同 resource ID、相同地址或定期 TTL 证明缓存仍有效；无法证明安全的部分继续完整读取。
5. 保持消费者所需 row 字段和语义一致，包含诊断字段；读取统计可不同，不伪造完整读取成本。
6. 缓存失效、短读、异常值、manager 搬迁、slot/entity/config 改变时，丢弃该快速结果并完整重建；完整读取也失败时清空 latest_row，不发送输入。
7. 每个 update 的完整回退尝试有界，不能递归重试或在异常状态形成无限循环。

优先让缓存复用静态解析结果和已定位组件，同时保留必要依赖验证。P1 自带的缓存有效性校验属于正确性要求；这不授权实施 P4 的“仅保留武器 identity guard”。若完整安全检查使收益低于预想，应报告实测结果，不通过删检查凑收益。

验证：同一内存时刻完整 row 与快速 row 做字段对照；覆盖各弹药类型、膛内弹、双弹匣选择、切槽、同资源不同实体、死亡/重生、组件搬迁、ownership/config 改变、静态 map 内容改变及读取中途变化。确认不接受失效数据且发送前两条路径仍完整复核。

完成条件：稳定上下文日常完整解析减少、总读取量实测下降；异常失效测试通过，原控制器语义测试通过。暂不承诺数量级或百分比。

### P2：固定前台 120 Hz 采样

仅给日常 snapshot 增加时间调度。input_probe、release_reload、auto_reload_step、continuous_reload_step 和 original_update 仍每个 update 执行。日常采样预算不包含低频的发送前完整复核，其成本单独列出。

- 前台目标 120 Hz，后台保留现有约 20 Hz 的行为。首次读取及重新获得焦点应及时采样并重置调度。
- 采用累计时间/绝对期限并保留余量，处理浮点误差与毫秒量化。不能直接每次设为 `now + interval` 并宣称 144 FPS 下能达到 120 Hz：该写法会因帧对齐降到约 72 Hz。
- 每个 update 最多一次日常采样，长帧不补跑多轮读取；丢弃积压时记录实际频率。低帧率下采样频率受 update 限制。
- 未到期不改 latest_at；长暂停/焦点切换不能使用过期上下文发送。按键释放的 0.08 秒和至少隔一次 update 的约束保持原样。
- 固定采样新增的检测延迟必须测量；120 Hz 不保证捕获高射速下持续不足一个采样间隔的 count==1，也不保证最后一发不打出。

验证：完整 update 调度测试覆盖上述帧率、抖动、毫秒时间、长帧、焦点切换、按键释放失败及点击重试；检查实际频率、无补采突发、row 新鲜度、控制器调用频率、发送原因/次数和触发时刻。以时间一致的弹药/输入轨迹比较基线，不能只测拆出的策略函数。

完成条件：高帧率日常采样不再随 FPS 无限增长，目标频率及误差有数据；完整复核和输入时序保持；原测试和新增回归测试通过。若采样导致已支持场景漏触发，先修正调度或在风险场景保持原频率，不强行宣称等价。

第一步独立交付：P0–P2 源码、离线结果、tactical 安装包及简短实机步骤，更新 STATUS。P3 在第一步证据与验收状态明确后单独推进；用户已确认总范围到 P3，不把阶段划分变成重复授权。

## 4. 第二步：P3 自适应采样

以 P2 为对照，只改变日常采样调度，复用同一读取器、统计和发送复核。30/60/120 Hz 是候选值，不能直接视为所有武器的安全频率。

| 状态 | 初始候选策略 | 必要条件 |
|---|---|---|
| 远离阈值、稳定且未射击 | 30 Hz | 能建立保守的消耗裕量；否则维持 120 Hz |
| 接近阈值但尚未进入窗口 | 60 Hz | 裕量覆盖下一次采样可能消耗及调度误差 |
| 射击/新点击/战术窗口/余量≤1 | 120 Hz，并及时提升期限 | 短暂 count==1 或高速 immediate 场景仍需轨迹验证 |
| 请求后等待恢复 | 初期保持 120 Hz | 不以 R 已发送推断正在换弹；证实不会影响续装/重试后才考虑 30–60 Hz |
| 未知配置、Heat、attack-only、读取不确定 | 保守沿用 P2 | 没有安全依据时不降频 |

细化要求：

- 新射击输入边沿触发及时采样/提频，持续射击保持高频；输入探测仍每个 update 执行。P3 的即时采样与速率统计须清楚区分，不隐藏额外成本。
- 邻近阈值不能统一硬编码为 `limit + 3`。结合配置的弹匣/总弹口径、已观察消耗、下一采样间隔和余量；未知射速、一次多发或骤降时不得依赖平均消耗证明安全。
- 提频立即生效，降频有稳定条件/滞回，避免每帧在频率档位间振荡。
- 切枪、焦点切换、缓存重建、装填恢复和读取失败重置调度；不得继承旧武器的低频期限。
- 逐发续装按原 0.1 秒请求间隔运行，普通失败重试及 attack-only 新点击保留；低频等待不能吞掉触发条件。

验证：以 P2 对照相同轨迹，覆盖高速自动、半自动快速连点、零阈值、总弹阈值、逐发续装、attack-only、Heat 和失败重试；比较触发原因/次数/时刻、空仓恢复、读取量和档位分布。重点构造跨阈值、短暂一发及采样边界点击，而非只测稳定高弹药。

完成条件：安全可降频场景平均读取量较 P2 进一步减少，风险场景保守回退；无已支持行为回归。无法证明安全的类别保持 P2，不扩大到 P4–P6。
